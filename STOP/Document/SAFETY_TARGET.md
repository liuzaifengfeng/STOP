# 无线急停系统最终安全目标

## 1. 文档状态与适用范围

本文档描述本项目的**最终安全目标、设计边界和验证方向**，用于指导后续硬件、固件、无线协议、BLE 工具箱和 OTA 功能的设计。

当前项目尚未完整实现或验证本文档中的全部要求。本文档不是产品认证、合规声明或安全等级证明。在完成正式风险评估、硬件故障分析、软件验证、环境试验和第三方评估前，设备应视为实验性“无线远程停机装置”，不得宣称达到特定 PL、SIL 或工业安全认证等级。

预期应用场景：实验室设备调试期间，由便携式急停按钮盒向断电控制盒发送停止请求，控制盒切断实验设备的危险电源。后期可增加电流检测、接触器状态检测和分级断电逻辑。

设计和评估时应结合适用地区法规及设备风险，参考但不限于：

- ISO 12100：机械安全风险评估与风险降低。
- ISO 13850：急停功能设计原则。
- ISO 13849-1：安全相关控制系统设计与性能等级方法。
- IEC 60204-1：机械电气设备及急停相关要求。
- IEC 62745：机械无线控制系统要求。
- IEC 60947-5-5：机械锁存式电气急停装置。

## 2. 核心安全原则

### 2.1 控制平面隔离

系统分为两个逻辑平面：

1. **安全控制平面**：急停按钮、E22 无线链路、安全状态机、输出驱动、接触器及其反馈。该平面必须在网页、手机、BLE、互联网和云端全部不可用时独立工作。
2. **维护管理平面**：BLE、网页或手机 App、参数管理、日志、诊断、OTA 和手动测试。该平面不得绕过、屏蔽或降低安全控制平面的保护。

BLE、网页、手机 App 和云端均不得成为急停动作链路中的必要组成部分。

### 2.2 失效安全

系统应优先采用“持续满足全部安全条件时才允许供电”的设计。发生以下任一事件时，断电控制盒应进入安全断电状态并锁存：

- 收到有效急停报文。
- E22 心跳超过规定时间未更新。
- 连续收到损坏、非法、重复或认证失败的安全报文。
- 按钮盒两路触点状态不一致。
- 按钮盒电池进入无法保证可靠工作的危险低电量状态。
- 按钮盒或控制盒复位、看门狗触发或自检失败。
- 无线模块、输出驱动或接触器反馈异常。
- 进入 OTA、维护测试或影响安全功能的参数修改流程。
- 系统无法证明自身处于允许供电状态。

不确定状态必须按危险状态处理，即“无法确认安全时断电”。

### 2.3 不自动恢复

- 上电或复位后默认保持断电。
- 无线通信恢复不得自动重新供电。
- 旋开或释放机械急停按钮不得自动重新供电。
- BLE 重连、网页刷新、手机 App 重启或云端恢复不得重新供电。
- OTA 成功、OTA 回滚或固件重启后不得自动重新供电。
- 恢复供电必须经过接收控制盒附近的本地人工复位。
- 复位只恢复“允许供电”条件，不得直接启动被控实验设备。

## 3. 建议系统结构

```text
急停按钮盒
  机械锁存急停按钮
      -> 两路触点独立采集
      -> MCU 自检、看门狗、电池检测
      -> E22 安全报文、心跳、序号、认证、冗余发送

断电控制盒
  E22 接收
      -> 报文验证与链路监控
      -> 安全状态机
      -> 安全继电器或接触器驱动
      -> 接触器辅助触点反馈
      -> 实验设备电源

维护终端
  云端 HTTPS 网页或原生手机 App
      -> BLE
      -> 状态、日志、诊断、受限参数、OTA
```

上游断路器负责短路和过载保护；急停断电宜由适合该用途的接触器、安全继电器或具有合适脱扣与反馈能力的装置执行。风险较高时，应评估双接触器串联、触点粘连检测以及本地有线急停作为独立兜底的必要性。

## 4. 安全状态机目标

建议至少包含以下状态：

- `BOOT_SELF_TEST`：启动、自检，输出保持断开。
- `TRIPPED`：安全断电，等待满足复位前提。
- `ARMED`：链路和硬件健康，允许输出保持供电。
- `EMERGENCY_STOP`：急停按钮动作导致的锁存断电。
- `LINK_LOST`：通信超时或报文异常导致的锁存断电。
- `HARDWARE_FAULT`：触点、驱动、电源、看门狗或反馈异常。
- `MAINTENANCE`：维护、参数写入或诊断状态，危险输出保持断开。
- `OTA_LOCKOUT`：升级和重启期间，危险输出保持断开。

从任何状态进入异常、维护或不确定状态时，系统应优先转入安全断电。只有本地人工复位、按钮已释放、链路稳定、硬件反馈正常、自检通过并持续满足规定时间后，才允许从断电状态返回 `ARMED`。

具体心跳周期、超时时间、重复发送次数和恢复稳定时间必须通过风险评估、停止时间测量、无线干扰试验和误动作容忍度确定，不能仅凭开发体验设定。

## 5. 无线安全报文目标

安全报文应保持短小、固定结构和确定性处理。建议至少包含：

- 协议版本和消息类型。
- 产品类型、发送端唯一设备 ID 和配对关系标识。
- 急停状态以及可检测存储或传输错误的冗余编码。
- 两路机械触点的独立状态或诊断结果。
- 单调递增序号或防重放计数器。
- 发送端运行计数和故障标志。
- 电池状态或低电量故障标志。
- 数据完整性校验。
- 基于设备密钥的消息认证码，用于识别伪造与重放。

CRC 只能用于发现随机传输错误，不能代替设备认证和防重放设计。接收端不得因收到格式正确但序号陈旧、来源错误或认证失败的报文而维持供电。

急停事件应采用冗余发送，但不能依赖“一次急停报文必然送达”。接收端必须持续监督正常心跳，心跳失效同样进入安全断电。

安全报文、诊断报文和网页手动收发报文必须在协议中明确隔离。手动发包功能不得构造急停解除、复位、保持供电或其他安全控制指令。

## 6. 输出和反馈目标

- 控制输出采用失电进入安全状态的电气结构。
- MCU、无线模块或驱动电源丢失时，危险电源应自动断开。
- 输出器件应具备适当的电压、电流、浪涌、短路和寿命裕量。
- 应读取接触器辅助触点或等效反馈，检测命令状态与真实触点状态是否一致。
- 检测到触点粘连、驱动短路或无法断开时，系统必须锁存故障并产生明确告警。
- 不得仅根据软件变量推定电源已经切断。
- 应评估所有危险能量，而不仅是单一路交流供电，包括储能、电容、气动、液压和设备自身后备电源。

## 7. BLE、网页与手机 App 的安全边界

维护客户端允许执行：

- 查看按钮、链路、电池、接触器反馈和状态机状态。
- 查看丢包率、序号异常、复位原因和历史事件。
- 读取与修改经过范围约束的非安全参数。
- 在安全断电状态下进行诊断和受限的 E22 手动收发测试。
- 在满足升级联锁条件时执行 OTA。
- 导入、导出配置和诊断报告。

维护客户端不得执行：

- 远程解除急停或清除安全锁存。
- 强制闭合接触器或绕过输出反馈。
- 关闭失联断电、看门狗或安全自检。
- 在设备带电运行时升级安全控制固件。
- 任意修改经过风险评估确定的安全超时、联锁和断电上限。
- 通过调试接口注入安全控制报文。

连接 BLE 本身不代表客户端已经通过产品身份认证。设备应在进入维护模式后执行独立认证；高风险维护操作还应要求物理按钮、短时维护窗口或控制盒本地确认。

## 8. BLE 客户端兼容目标

BLE 协议必须独立于网页实现，使云端网页、Android/iOS 原生 App、桌面程序和未来的现场网关可以复用同一套设备协议。

建议设备暴露稳定的自定义 GATT 服务：

```text
Device Management Service
  CONTROL      Write with response   短命令、参数请求、事务控制
  BULK_DATA    Write without response OTA 等大块数据
  EVENT        Notify                状态、收包、日志和进度事件
  STATUS       Read + Notify         能力、版本和当前状态
  BULK_ACK     Notify                分块确认、期望偏移和错误码
```

应用层协议不依赖 JavaScript 对象或特定操作系统 API。控制消息应有版本、请求 ID、操作码、载荷长度和明确错误码；批量数据应有事务 ID、偏移、长度和校验。协议规范和测试向量应独立保存，以便各客户端使用相同结果验证实现。

网页使用 Web Bluetooth 作为传输适配层；原生 App 分别使用 Android/iOS BLE API。UI 和传输 API 可以不同，但 GATT UUID、命令语义、分包、认证、错误码和 OTA 状态机保持一致。

## 9. OTA 最终安全目标

- 按钮盒和接收盒使用不同产品标识，禁止交叉刷写。
- 固件清单至少包含产品类型、硬件版本、固件版本、长度、SHA-256 和数字签名。
- 设备端独立验证镜像和签名，不能只相信云端网页的检查结果。
- 固件写入备用 OTA 分区，当前有效固件在传输失败时继续可启动。
- 支持按可靠偏移续传，不能仅依赖浏览器认为数据已经写入。
- 接收控制盒开始 OTA 前必须断开危险输出并验证反馈。
- 按钮盒开始 OTA 前，接收控制盒必须进入锁存断电状态。
- OTA 期间拒绝与安全维护无关的参数写入和手动发包。
- 新固件启动后执行自检并显式确认有效；自检失败自动回滚。
- OTA 成功、失败或回滚后均保持安全断电，等待本地人工复位。
- 记录升级来源、版本、时间、结果和失败原因。

## 10. 电流检测与高级断电逻辑

电流检测可用于：

- 验证断电后负载电流是否下降到安全范围。
- 辅助检测接触器粘连或错误接线。
- 识别异常启动、过流、欠流、堵转或负载消失。
- 保存急停前后的诊断数据。

电流算法不得阻止或无限延迟急停动作。若未来需要“先通知设备正常停机，再强制切电”，应采用有硬上限的两阶段流程：

1. 发出普通受控停机请求。
2. 等待经过风险评估确定的固定最长时间。
3. 无论普通停机是否成功，安全链路都在期限到达后强制切断危险电源。

该最长等待时间属于安全参数，不得由云端自由修改。

## 11. 软件架构目标

建议逐步拆分为：

- `safety_manager`：唯一安全状态机与输出许可判断。
- `radio_service`：E22 底层收发、链路质量和报文分发。
- `safety_protocol`：安全帧编码、认证、序号和超时监督。
- `output_monitor`：接触器驱动、反馈与故障检测。
- `config_service`：参数验证、持久化、版本迁移和安全参数保护。
- `ble_manager`：GATT、客户端认证和维护会话。
- `ota_service`：镜像接收、续传、校验、切换和回滚状态。
- `diagnostics`：复位原因、事件记录和只读统计。

HTTP、BLE 回调和调试接口不得直接驱动接触器或直接操作 E22 安全状态。所有请求必须通过有界队列和明确权限进入对应服务；`safety_manager` 是输出许可的唯一决策者。

底层无线接收队列应只有一个消费者，再由分发层复制给安全协议、业务逻辑、诊断终端和日志，避免多个任务争抢同一报文。

## 12. 验证目标

至少应设计并记录以下测试：

- 急停按钮正常动作和机械锁存。
- 丢包、延迟、重复、乱序、旧序号和伪造报文。
- 强无线干扰、遮挡、边界距离和多套设备同时运行。
- 按钮盒与控制盒分别掉电、复位、死机和看门狗触发。
- E22 无响应、UART 故障、AUX 异常和配置损坏。
- 按钮双触点不一致、输入短路和断路。
- 输出驱动短路、接触器拒动和触点粘连。
- BLE 连接、断开和恶意命令不能影响安全状态。
- OTA 中断、断电、错误产品、错误硬件版本、损坏和签名失败。
- 新固件启动失败后的回滚与断电保持。
- 电池低电量、快速电压跌落和电池拆除。
- 急停总响应时间和被控设备实际危险能量消散时间。

所有测试应有可重复步骤、期望结果、测量结果和版本记录。最终需要根据具体被控设备的风险评估确定目标 PL/SIL、诊断覆盖、架构类别以及是否需要独立或认证安全器件。

## 13. 分阶段实施建议

1. 移除或隔离现有自动休眠和循环发包测试逻辑，建立确定性的安全状态机。
2. 完成失联断电、急停锁存、本地人工复位和输出反馈。
3. 重构 E22 接收分发，增加设备 ID、序号、认证和故障统计。
4. 建立 BLE 只读状态与日志通道。
5. 加入受限参数读写和维护模式联锁。
6. 实现带分块确认、续传、签名和回滚的 BLE OTA。
7. 增加电流检测及接触器诊断，但保持急停硬截止路径独立。
8. 根据风险评估完成硬件冗余、故障分析、环境测试和安全验证。

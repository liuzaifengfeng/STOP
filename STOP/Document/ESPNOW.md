# E22 / ESP-NOW 工作模式

控制端 `STOP` 和被控端 `Assused` 使用同一套应用层配对、认证心跳、停机请求及回执。现在可以在网页上位机的“设备配置”中设置无线工作模式，无须更换固件版本。

| 模式 | 参数值 | 行为 |
| --- | --- | --- |
| E22 单通道 | 0（默认） | 沿用外置 E22；不启动 Wi-Fi |
| ESP-NOW 单通道 | 1 | 使用 C6 内置 2.4 GHz 无线；不依赖 E22 自检，E22 引脚设为休眠 |
| E22 + ESP-NOW 双通道 | 2 | 同一应用数据帧发往两条链路；接收端接受任一路有效心跳 |

## 操作顺序

1. 两端先升级本次固件。通过 BLE 分别连接控制端、被控端，进入“设备配置”。
2. 设置工作模式和 ESP-NOW 信道（1～11，默认 6），点击“验证并写入设备”。网页会保存后重新读取，核对参数一致。
3. 模式和信道保存到 NVS，**重新上电后生效**。先断开被控端输出，再分别重启两端；概览和配置页会显示当前运行模式。配置页的下拉框显示已保存/待保存的下次启动值。

两端建议设置相同模式；使用 ESP-NOW 的两端必须同信道。双通道与单通道设备也可通过共有的链路通信。ESP-NOW 无需路由器、SSID 或密码，网页仍通过 BLE 管理设备。

已有设备身份使用 BLE MAC，保留原有 NVS 配对记录，切换模式不改变身份。如果尚未配对：保持控制端急停，长按被控端本地按键 8 秒打开 30 秒配对窗口；配对成功、控制端急停释放并收到连续有效心跳后，长按被控端本地按键 3 秒后释放，执行原有本地使能确认。

## 双通道语义

- 这是并行冗余模式，**不是按距离或 RSSI 自动选择一路**。距离不能由 RSSI 可靠换算；网页原有 RSSI、RTT 和成功率来自电脑到设备的 BLE 维护连接，不能用来判断控制端到被控端的 E22 / ESP-NOW 链路质量。
- 同一心跳在两路使用相同启动编号和序号，已有序号检查只计入一次，重复包不刷新心跳截止时间。控制端同一轮配对确认也只处理一次。
- 任一路持续送达有效心跳即可维持连接；所有链路均未送达有效心跳达到原有 800 ms 截止时间后，被控端安全任务撤销输出许可（实际动作还受任务调度影响）。恢复通信后仍需本地确认。
- E22 使用独立发送任务和单槽最新帧队列，不因 AUX 等待阻塞 ESP-NOW。未发送且已排队 200 ms 的旧帧丢弃；Wi-Fi 接收回调只入队，队列中超过 200 ms 的 ESP-NOW 包不交给业务层。单槽可能合并连续重发；诊断发送成功表示已接受发送，不承诺双路或对端收妥。
- 一条链路初始化失败时，双通道可通过另一条继续运行；启动串口日志分别列出 E22 / ESP-NOW 初始化结果。网页 `READY` 表示至少一条链路初始化可用，不表示远端在线或两路均健康。链路运行中失联由认证心跳截止时间判断。
- 低电量停机、OTA 维护、传感器故障、急停、本地使能条件保持原逻辑；无线发送完成回调不替代应用层 `STOP_ACK`，更不替代输出电压确认。

## 协议与限制

新增配置 TLV 均为 `U32`：`0x0004` 为工作模式（0～2），`0x0005` 为 ESP-NOW 信道（1～11）。默认值兼容旧 NVS；旧上位机只写原参数时保留新增配置。新上位机连接旧固件时不发送新参数。

设备状态 `radio_mode` 原有 0～4 保留，5 表示 ESP-NOW，6 表示双通道。`radio_ready` 仍为布尔值。诊断载荷仍为 1～235 字节，`SR` 安全帧不允许从 BLE 诊断发送入口注入。

ESP-NOW 采用广播承载，以复用原有 BLE MAC 应用身份，无须额外维护 Wi-Fi MAC 映射。安全业务帧仍检查目标身份、配对密钥 HMAC、启动编号和序号。**广播未使用 ESP-NOW 的链路加密；原有配对确认明文传递密钥，因此本实现不提供安全密钥协商或保密性。** 配对方式沿用原型协议，不能把它理解为已完成生产级安全认证。

后续若实现按质量动态选路，应先增加各链路的双向探测和独立 ACK、丢包统计，再设置切换阈值、恢复滞回及停机优先规则。目前没有实现距离估计或质量自动选路。

官方 API 依据：[ESP-IDF 5.5.3 ESP32-C6 ESP-NOW](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c6/api-reference/network/esp_now.html)。当前构建使用 ESP-IDF 5.5.3，启用 Wi-Fi / BLE 软件共存。

```powershell
platformio run -d STOP
platformio run -d Assused
python tests/test_stop_ack.py
python tests/test_radio_transport.py
node tests/test_web_radio.mjs
npm --prefix web run build
```

主机测试覆盖两端实际 C 编解码、认证回执、新参数范围与回读、NVS 重载、单/双通道选择、单链路初始化失败、双链路失败、过期收包和发送超时后迟到回调隔离。

尚需两块实物验证：三种模式下配对/急停/本地恢复；单路中断与双路中断；同信道及异信道；BLE 连续操作和 OTA 共存；低电量停机回执与输出电压；实际失联断电时延、距离、干扰与功耗。编译和 SDK 替身测试不能代替这些射频、时序及输出硬件验证。
